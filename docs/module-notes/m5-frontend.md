# M5 模块说明 — 前端（SSE 流式问答 + 来源可追溯）

> 规格书 9.1-1：每个模块交付时附带三段说明（为什么这么设计 / 会被问什么 / 怎么答）。
> 覆盖 `frontend/`（`App.vue` / `api.js` / `components/*`）与 M5 为前端补的两处后端改动
> （`app/api/chat.py` 的 SSE 端点、`app/agent/*` 的分块推送与 `done` 载荷）。

## 1. 为什么这么设计

**为什么 SSE 用 FastAPI 原生 `StreamingResponse`，不引 `sse-starlette`。**
本项目的既定取向是「够用且可控、不引额外依赖」。SSE 一帧就是三行字符串
（`event:` 行 + `data:` 行 + 空行），原生 `StreamingResponse` 足够 —— 为省这几行引一个包不划算。
`X-Accel-Buffering: no` 关掉反代缓冲（否则流会被攒起来一次性吐给前端，看起来像没流式）。

**为什么前端不用 `EventSource`，而用 `fetch` + `resp.body.getReader()`。**
规格书 §M5 交付原文写「原生 `fetch` + `EventSource`」，但 5.2 把问答定义为 **`POST /api/chat`**
（请求体带 `session_id` + `question`，还可能是长文本），而浏览器原生 `EventSource` **只能发 GET**。
用它就得把问题塞进 query string 并另开一个 GET 端点 —— 为迁就一个客户端类去改服务端契约。
`fetch` + `ReadableStream` 是原生能力，能发 POST 也能逐帧读 SSE。已登记 DECISIONS。

**为什么状态不引 Pinia。**
单页只有一个会话，状态就是「消息数组 + 输入框 + busy」。引 Pinia 等于把一个 `ref` 换成
store + actions，没有任何收益（9.2 最简依赖）。**注意一个 Vue 陷阱**：往 `ref` 数组里 push
**裸对象**后，再改裸对象不会触发更新 —— 故每条助手消息用 `reactive()` 包一层，
后续在事件回调里按字段改才能被追踪到。

**为什么过程展示只显示「已发生」的节点，不预测后续。**
1.6 第 4 条要的是「当前在跑哪个节点」。若预先画出完整节点链再逐个点亮，
**「实际没跑」的节点看起来也像「跑过了」** —— 正是本项目一路在防的静默失败。
故 `ProcessPanel` 只消费 `node_start` 事件，到达一个画一个。

**为什么「当前节点」用静态样式而不是脉动动画。**
1.6 明确把「动画特效」列进**不做**清单。过程指示需要区分「已完成 / 进行中」，
用**实心点 + 描边环 + 字重/颜色**已足够，无需动画 —— 不为了视觉效果去踩边界。

**为什么来源卡片要展开 evidence 原文，而不只给一行标题。**
1.6 第 3 条要求「每条回答下方的来源卡片」，1.5/4.11 的核心卖点是「可追溯」。
只给一行标题等于「说了来源但看不到依据」；卡片用原生 `<details>` 展开
**evidence 原文 + `source_url` + `patch`**，把「可追溯」落到实处（不引 UI 库）。

**为什么正文是「先校验、后分块推」而不是「边生成边推」。**
M5 验收要求「SSE 流式逐字显示」，但 M4 的 guard 要求「完整正文校验通过才交付」：
G2（英雄名越界）要拿全篇英雄名比对、G3（类别化外推）要按句子窗口判，**都必须完整正文**。
若边收边推，未校验内容会先到前端 —— **推出去就撤不回**，等于把 guard 架空。
故在**校验通过后**把正文按块推（每帧 ≤ 8 字）：协议上仍是多帧流式（前端逐段 `append`），
但交付给用户的每一个字都已通过校验。取舍方向与 M4 一致：**校验优先于观感**。

**为什么 `done` 事件要补 `clarify_options` 与 `intent`。**
5.3 原协议 `done` 只有 `type` / `confidence`。但 1.6 第 5 条要求澄清反问「差异化展示」，
拿不到候选就没法把候选渲染成可点选项 —— 差异化只剩一个标签，等于没做。
故对 5.3 做**有意扩展**（与 M4 的 `thinking` 同类），已登记 DECISIONS。

**为什么 `session_id` 放 `sessionStorage` 而不是 `localStorage`。**
1.6 明确不做「历史会话管理页」。`sessionStorage` 让**刷新保留上下文、关标签即清空**，
恰好匹配「单页单会话」；`localStorage` 会跨标签/跨天残留一份看不见的旧上下文，
下次打开时的串味属于静默问题。

**为什么 SSE 路径唯一的 `except` 是把异常转成 `error` 事件。**
HTTP 响应头在流开始时就已发出，流中途抛异常**无法再改状态码**；不转成 `error` 事件的话，
前端只会看到连接莫名中断（静默失败）。故转成事件**为了让前端可见**，同时用
`logger.exception` 打完整堆栈 —— 不是为了把错误藏起来。
`/api/chat` 里**没有**兜底 Neo4j 的 try/except：降级是 `graph_query` 节点的职责，
本层再包一层会把真正的编程错误（如 State 字段拼错）一起吞掉。

## 2. 会被问什么

1. 为什么不引 UI 库 / Pinia？单页状态怎么管？踩过什么坑？
2. 为什么用 `fetch` 而不是 `EventSource`？规格书不是写了 `EventSource` 吗？
3. SSE 帧怎么解析的？`\r\n` 怎么办？半帧怎么处理？
4. 「流式逐字显示」是真逐字吗？为什么不是边生成边推？
5. 过程展示为什么不预画整条节点链？
6. 来源卡片展开的是什么？怎么保证 citation 和 evidence 对得上？
7. 拒答 / 澄清 / 低置信怎么差异化？为什么按 `type` 分而不是按文案猜？
8. 澄清候选从哪来？5.3 协议里有吗？
9. 后端 SSE 端点为什么不用 `sse-starlette`？为什么没有兜底 Neo4j 的 try/except？
10. 前端连不上后端会怎样？

## 3. 怎么答

- **不引 UI 库 / Pinia**：1.6/9.2 的边界要求。单页单会话，`ref`/`reactive` 足够；
  引 Pinia 只是把 `ref` 换成 store + actions。**踩过的坑**：往 `ref` 数组 push 裸对象后改裸对象
  不触发更新，助手消息必须用 `reactive()` 包一层。
- **`fetch` 而非 `EventSource`**：`EventSource` 只能 GET，而 5.2 定义问答为 `POST /api/chat`；
  用 `fetch` + `ReadableStream` 既发 POST 又能逐帧读 SSE（原生能力，不引依赖）。偏离已登记 DECISIONS。
- **SSE 解析**：把 `\r\n` 归一化为 `\n`（某些代理会改写行尾），按 `\n\n` 分帧，
  半帧留在缓冲里等下一块；单帧 JSON 解析失败只丢弃该帧，不让整轮回答断掉。
- **逐字显示的口径**：正文在 **guard 校验通过后**按块推（每帧 ≤ 8 字），前端逐段 `append`。
  **不是逐字符，也不是边生成边推** —— 因为 G2/G3 必须拿完整正文才判得准，
  未校验内容一旦推出去就撤不回。取舍：**校验优先于观感**。
- **过程展示不预画**：只画 `node_start` 已到达的节点。预画会让「实际没跑」看起来像「跑过了」。
- **来源卡片**：`citation.index` 是 **1-based** 的 evidence 序号，卡片按 `index - 1` 取
  evidence **原文**展开，并显示 `source_url` / `patch`；图谱来源与文本来源用不同色标区分。
- **差异化渲染**：按 `done.type` 分档 —— `reject` 中性灰 + 「拒答」标、`clarify` 琥珀 +
  「需要澄清」标 + **候选可点选（点了填入输入框）**、`low_confidence` 提示色、`answer` 不加标记
  （正常回答不该有额外视觉噪音）。**依据是协议字段，不是猜文案**。
- **澄清候选**：来自 `done.clarify_options` —— 这是对 5.3 的**有意扩展**（原 `done` 只有 type/confidence）。
- **后端 SSE**：原生 `StreamingResponse`（一帧三行字符串，不值得引包）；
  唯一的 `except` 把异常转 `event: error`（流已开始无法改状态码，不转的话前端只看到连接中断），
  同时 `logger.exception` 打堆栈。**本层不兜底 Neo4j** —— 降级是节点职责，兜底会吞掉真 bug。
- **连不上后端**：`/api/health` 探测失败时顶部三个状态灯全红并显示「后端未连通」，
  底部给一条横幅提示启动 uvicorn；提问失败在气泡内显示错误，不会静默无响应。
