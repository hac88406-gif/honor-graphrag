**如实说明**：本轮诱导集**未触发 guard**，故 A/B 两组数字相同——**这一项没有测出差异**，
不能据此宣称「guard 无价值」。guard 的实际作用机制在受控探针上可见：
放松前 6 条被拦回答**全部回落确定性组装**（证据罗列，构造上不含归纳），
即 guard 不改写答案、只把越界答案换成有据罗列。**这是本轮 A/B 的局限，不是结论。**

**（d）方法论修正（本轮发现并已落地）**：此前 guard 判否即回落、**原始正文不落盘**，
误报率只能靠「同题同资料重新生成一次再判」近似——而重采样常复现不出当初那句话，
**会把真越界记成误报**（`M6-guard-blocked-raw-preAudit.json` 里 T-04 的 `detail`
「怕妲己这类高爆发法师」正是典型 G3 越界形态，却因重采样判成 FP）。
本轮已在 `generate.py` 落地 `raw_answer` 留痕，脚本优先判**当初真正被拦的那一段**
（`source=captured`），仅旧记录回退重采样并标注 `source=resampled`，两者不混算。

#### 2.6.1 G3 的 R1 豁免粒度收窄（审核后·需求方第 2 项）

**旧口径（缺陷）**：问题文本里出现「为什么 / 为何 / 原因」即**整条关闭 G3** —— 这是一个
**按问题措辞触发的全局开关**，而不是按答案内容判定。需求方实测：答案「后羿怕高爆发法师」在
问句含「为什么」时被**放行**（该放行是错误的，答案把克制关系抬成了类别）。

**新口径（已落地）**：改为「**答案中的类别主张能否从 evidence 的 reason 溯源**」——
命中片段若能在 `_evidence_corpus(evidence)` 找到出处，判为**引述**（豁免）；否则判 G3 越界。
删除死常量 `_REASON_QUESTION`，模块头注释同步改写（`app/llm/guard.py`）。

**验证（`M6-g3-coverage-output.txt`）**：需求方给的 3 条实测例，在当前规则下**全部被拦下**：

```
拦下  答案='后羿怕高爆发法师。'        问题='后羿怕哪些英雄？为什么？'  reason=class_leak
拦下  答案='后羿的克星是高爆发法师英雄。' 问题='后羿怕哪些英雄？为什么？'  reason=class_leak
拦下  答案='后羿怕高爆发法师。'        问题='后羿怕什么'               reason=class_leak
```

**代价标注**：G3 属**安全向**校验，**漏拦的代价高于误拦**，故按裁定**偏严执行**；
收窄只针对「按问题文本整条开关」这一原则缺陷，不放松对类别外推本身的判定。
边界由 `tests/unit/test_generate_guard.py` **21 条单测**钉住（删 3 条旧 R1 口径、新增 4 条新口径）。

### 2.10 评测可复现性：三层修复（需求方二审裁定）

**根因（需求方定位）**：代码 / `.env` / `.env.example` **完全没有** temperature / seed 设置，
LLM 客户端**走 API 默认采样值** → 随机性高：同问句 + 同依据两次跑批，78 条候选答案里可差 **47 条**。
后果：**指标不可复现，审核结论不可采信**。按需求方三层要求逐层修复。

#### 2.10.1 第一层：采样参数显式下发 + 全链路留痕

| 落点 | 改动 |
| --- | --- |
| `app/config.py` | 新增 `LLM_TEMPERATURE=0.0` / `LLM_SEED=42`（注释说明「seed 不保证确定性，稳定性靠固化答案集」） |
| `app/llm/client.py` | `CloudChatClient` 新增 `temperature` / `seed` 形参；`_payload` **显式下发**（此前完全不下发）；`LLMResult` 新增 `temperature` / `seed` 字段；模块头新增「采样参数必须显式下发」契约 |
| `app/agent/nodes/generate.py` | `generation` 留痕追加 `temperature` / `seed`（事后可核对「这批用什么参数跑的」） |
| `.env.example` | 同步 `LLM_TEMPERATURE=0.0` / `LLM_SEED=42` 示例与说明 |
| `DECISIONS.md` | 追加裁定「评测必须确定性：温度/seed 显式下发」 |

判官（`eval_judge.py`）与被测生成**同一套参数**，避免「判官随机、被测固定」的不对称。

#### 2.10.2 第二层：确定性实测（结论：**参数无法保证逐字一致**）

`scripts/measure_determinism.py`：从 `M6-eval-raw.json` 取**真实问句 + 真实依据**、
prompt 走生产路径 `build_messages`，A / B 两轮各跑 3 次、共 5 组：

```
【A·仅 temperature=0（seed 不固定）】1/5 组逐字一致
【B·temperature=0 + 固定 seed=42】 2/5 组逐字一致
      -> 未达标：推理模型（v4-pro）存在内置非确定性，与 seed / temperature 无关
```

例：`铠被谁克制` 三次正文为「根据资料，克制铠的英雄有：…」/「铠被以下英雄克制：…」/「铠被…克制。」
——**语义等价但逐字不同**。原始输出见 `M6-determinism-output.txt`。

**处理（按需求方要求）**：① **不硬报单次数字**；② 云端**接受** seed，故固定 `seed=42` 作为
「尽力而为」的随机性压缩手段，但**不把确定性寄托在参数上**；③ 稳定性改由第三层**固化答案集**保证。

#### 2.10.3 第三层：固化答案集 + 增量跑批（`--reuse-answers`）

- `docs/milestones/M6-golden-answers.json`：**147 turn** 的固定答案，头部落盘
  `llm_model=deepseek-v4-pro` / `llm_temperature=0.0` / `llm_seed=42` / `updated_at`。
  **所有判定（guard / 判官 / 人工复核）一律基于这一份答案**——这是指标可复现的唯一来源。
- `scripts/run_eval.py` 新增 `--reuse-answers`：命中固化集即复用、不重新生成；每轮结束把结果并入固化集，
  并打印「复用 / 新生成」条数（本轮全量首跑：复用 **0/147**、新生成 **147**，符合预期）。
- **边界（写进脚本模块头与 `DECISIONS.md`）**：`--reuse-answers` **仅适用于离线可验证的改动**
  （guard 规则、判官口径、统计口径）；**检索 / prompt / 生成模型的改动不得复用**——
  答案会变，必须重生成，否则等于拿旧答案给新系统打分。

**修复效果**：

| 项 | 修复前 | 修复后 |
| --- | --- | --- |
| 采样参数 | 完全不下发，走 API 默认值 | `temperature=0.0` / `seed=42` 显式下发，`LLMResult` + `generation` 双留痕 |
| 答案稳定性 | 同问句同依据两次跑批差 **47/78** 条 | 判定基准固定（147 turn 固化集），跨批次可比 |
| 判定成本 | 每次改动全量重生成（重复计费） | 离线可验证改动 **0** 次重生成 |
| 有据率数字 | 94.8%（判定对象已不存在） | **98.7%**（基于固定答案，可复现） |

1. **首 token 延迟未达 3.4 目标（llm 生成路径 mean 4.22s > 2.5s）**。
   原因（**审核后修正**）：**主因 = 推理模型的思考前置**（v4-pro 先输出 250~290 token 的
   `reasoning_content`，正文在其后才产生，首 token 被思考时间主导）；**次因 = guard 需完整正文**
   （G2 要拿全篇英雄名比对、G3 要按句子窗口判，未校验内容推出去撤不回）。
   **修正依据**：句级增量校验实测收益 **0.00s** —— 若「校验需完整正文」是主因，句级提前推送应有收益；
   收益为 0 说明瓶颈在正文产生**之前**（思考）。M5 原登记的主次（「校验优先于观感」）**被实测推翻**。
   **模型对比（审核后补测）**：deepseek-chat 首 token **1.09s**（reasoning_tokens=0）**达标**、
   v4-pro **5.01s**（reasoning_tokens 均值 233），两者答案有据率**同为 7/7=100%** →
   该偏差属**选型/模型特性**，**不是**设计取舍造成。生成模型**保持可配置**（`CLOUD_CHAT_MODEL`，
   默认 v4-pro 质量优先，演示可切 chat）。范围澄清：拒答 / 澄清 / template 路径首 token **0.02s**，
   **只有「正常 answer + llm 路径」慢**。

2. **完整回答延迟长尾超 8s**（端到端全量 answer `max=19.69s`，mean 5.53s / p50 3.36s；流式 n=7 完整回答 mean 6.74s）。
   原因：`vector` 单路（如「貂蝉对线思路」）单次生成含 250~290 token 思考，且**样本量少**（n=68 中长尾几条）；
   均值与 p50 达标，**长尾如实记录**。

3. **泛化集检索 Recall@5 为 n/a**。原因：泛化集按「真实用户口吻」设计，**未标注
   `expected_evidence_contains`**（标注它会诱导出题人按标准答案反推问句，破坏泛化性）。
   Recall@5 在覆盖集上以 **26/26 = 100%** 报出。**这是一处口径缺口，如实标注，不补标注凑数。**

4. **guard on/off A/B 未测出差异**（诱导集 0 触发，两组均 100%）。见 §2.6(c) 局限说明。
   **不宣称 guard 无价值**——其作用在受控探针上可见（放松前 6 条被拦全部回落确定性组装）。

5. **一次全量 pytest 出现 1 次 Chroma 瞬时错误**（`hnsw segment reader: Nothing found on disk`），
   单独复跑检索层 8 条**全部通过**，判定为并发访问同一持久化目录的瞬时问题，非检索层缺陷。

6. **guard 生产路径可判样本仅 1 条**（最终跑批只拦下 M-02#2，判为真越界 → 误报率 **0/1 = 0.0%**）。
   原因：两条放松落地后，常规评测集极少触发 guard。**单条样本不足以支撑「误报率」这一比率指标**，
   故误报率的主证据仍是**受控探针**（放松前 6/6 = 100%，§2.6(b)）；生产路径数字仅作旁证，如实记录。

7. **答案有据率的判官有 1 条误报（判官噪声，非答案缺陷）**。人工抽检臂逐条复核发现：
   F-30#1 判官把**自己 prompt 里的「用户原问题」文本**误当成答案中的无据片段。
   影响：全量判官口径 97.4% 比人工复核后的 98.7% **低 1.3pt**。已如实标注（§2.4.1）；
   **不修改判官 prompt 去「凑高」**——判官口径一旦为结果让步就不再可信。8.2 要求人工复核 50% 正是为此。
   说明：上一版（未固化）的 3 条误报（B-03 / F-31 多意图告知文案、H-03 空答案幻觉）在固化答案集上
   **全部消失**，说明误报与**答案文本形态**强相关；遗留改进方向（M7）：判官前置剥离元信息 + 强制非空断言。
