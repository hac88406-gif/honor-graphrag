**口径与局限（如实记录）**：
- 判官与人工的一致率 **94.7% vs 94.9%（差 0.2pt）**，整体可信；但判官误报**集中在两类**：
  ① **多意图告知文案**被当成事实性陈述；② **空 / 短答案**上的幻觉。
  两类都出现在「判官要读的正文很短或含元信息」时——与本轮早先发现的「判官在长资料上被思考吃光返回空答案」
  是同一根因的另一面：**判官的注意力分配不稳**。
- 人工臂是**一次性人工复核**（`M6-grounded-human-verdicts.txt`），**不可自动重算**；
  抽样本身确定性可复跑（`measure_grounded_human.py`）。这正是 8.2 要求人工复核 50% 的理由。
- 判官臂与人工臂**不混算**：判官失败的样本从分母剔除并计数，**不得静默当成「有据」**。

**（a）生产路径触发率**（最终评测集 116 turn 中走 LLM 生成的 turn）：

**（b）误报率——分母为 0 时的处理**（8.2 + 需求方第 3 项）：

生产路径最终跑批 **0 条被拦下 → 误报率分母为 0，如实记录「无从计算」**。
为得到可判样本，另设**受控探针**（`measure_guard_fp.py`）：同一批模型回答分别过
「放松前规则」与「当前规则」，差异只来自规则本身、不受采样波动影响：

```

  放松前规则拦下 6 例（38%）  -> 判官逐条判：6 例全部 grounded=True  -> 误报率 6/6 = 100.0%
  当前规则  拦下 0 例         -> 误报率分母为 0
```

**放松前误报率 100% ≫ 20% 阈值 → 按裁定放松规则**，落地两条：

| 放松 | 触发形态（真实误报例） | 处理 |
| --- | --- | --- |
| **R3** 角色定位描述不判 G3 | 「东皇太一定位为游走/对抗路，**以压制为核心**」——「压制」是名词性打法描述，被正则误判成「克制某类英雄」 | 命中片段含「为核心 / 作为核心」即豁免 |
| **G2** 任一书写形式可溯源 | 「这版本打野强势的有哪些」——资料写简称「**木兰**」，答案忠实照写，只拿规范名「花木兰」比对就判成英雄越界 | 用 `heroes.json` 的别名表，规范名/别名任一命中即算可溯源；清单不可用则退回规范名比对，**不放大豁免** |

放松后**另取更早一次跑批**（`M6-guard-blocked-preRelax-raw.json`）里真正被拦下的 2 条
（T-05「压制为核心的游走/对抗路」、F-48「花木兰」）逐条判官判定**均为误报（FP）**，
与上述受控探针结论一致。

**（c）guard on/off 对「答案有据率」的 A/B**（需求方二审裁定 B-3，诱导集 21 条）：

```
A 组（guard ON ）答案有据率：21/21 = 100.0%
B 组（guard OFF）答案有据率：21/21 = 100.0%
A 组类别化外推（越界）条数：0
B 组类别化外推（越界）条数：0
guard 在诱导集上触发：0/21 = 0.0%
```

**如实说明**：本轮诱导集**未触发 guard**，故 A/B 两组数字相同——**这一项没有测出差异**，
不能据此宣称「guard 无价值」。guard 的实际作用机制在受控探针上可见：
放松前 6 条被拦回答**全部回落确定性组装**（证据罗列，构造上不含归纳），
即 guard 不改写答案、只把越界答案换成有据罗列。**这是本轮 A/B 的局限，不是结论。**

**（d）方法论修正（本轮发现并已落地）**：此前 guard 判否即回落、**原始正文不落盘**，
误报率只能靠「同题同资料重新生成一次再判」近似——而重采样常复现不出当初那句话，
**会把真越界记成误报**（`M6-guard-blocked-raw-preAudit.json` 里 T-04 的 `detail`
「怕妲己这类高爆发法师」正是典型 G3 越界形态，却因重采样判成 FP）。
本轮已在 `generate.py` 落地 `raw_answer` 留痕，脚本优先判**当初真正被拦的那一段**
（`source=captured`），仅旧记录回退重采样并标注 `source=resampled`，两者不混算。

### 2.7 `route_llm`（LLM 意图路径）对比与裁定

同一批 **108 条单轮问句**（已排除多轮追问——其期望值依赖指代消解，两条路径都拿不到上下文）：

## 4. 未达标项及原因（如实记录）

1. **首 token 延迟未达 3.4 目标（llm 生成路径 mean 4.22s > 2.5s）**。
   原因：M5 已定取舍「**校验优先于观感**」——guard 的 G2 要拿全篇英雄名比对、G3 要按句子窗口判，
   必须**完整正文**才判得准，未校验内容推出去撤不回。**M6 已按裁定评估句级增量校验**：
   实测整段答案只有 1 句、句级提前推送收益 **0.00s**，跨句依赖漏检 0/3 → **不切换**。
   即：**该偏差在现有架构下不可消除**，只能登记（README 已知偏差 + DECISIONS）。
   范围澄清：拒答 / 澄清 / template 路径首 token **0.02s**，**只有「正常 answer + llm 路径」慢**。

2. **完整回答延迟长尾超 8s**（全量 answer `max=29.3s`，均值 6.06s / p50 3.15s）。
   原因：`vector` 单路（如「貂蝉对线思路」）单次生成含 250~290 token 思考，且**样本量少**（n=68 中长尾几条）；
   均值与 p50 达标，**长尾如实记录**。

3. **泛化集检索 Recall@5 为 n/a**。原因：泛化集按「真实用户口吻」设计，**未标注
   `expected_evidence_contains`**（标注它会诱导出题人按标准答案反推问句，破坏泛化性）。
   Recall@5 在覆盖集上以 **26/26 = 100%** 报出。**这是一处口径缺口，如实标注，不补标注凑数。**

4. **guard on/off A/B 未测出差异**（诱导集 0 触发，两组均 100%）。见 §2.6(c) 局限说明。
   **不宣称 guard 无价值**——其作用在受控探针上可见（放松前 6 条被拦全部回落确定性组装）。

5. **一次全量 pytest 出现 1 次 Chroma 瞬时错误**（`hnsw segment reader: Nothing found on disk`），
   单独复跑检索层 8 条**全部通过**，判定为并发访问同一持久化目录的瞬时问题，非检索层缺陷。

6. **guard 误报率在最终跑批分母为 0**。原因：两条放松落地后，常规评测集不再触发 guard。
   **误报率因此无法在生产路径上重测**——这是放松的必然结果，如实记录。

7. **答案有据率的判官有 3 条误报（判官噪声，非答案缺陷）**。人工抽检臂逐条复核发现：
   B-03 / F-31 把**多意图告知文案**当成无据事实、H-03 在「资料不足。」这种**空答案**上幻觉出英雄名。
   影响：全量判官口径 92.2% 比人工复核后的 94.8% **低 2.6pt**。已如实标注并给出两类误报形态（§2.4.1）；
   **不修改判官 prompt 去「凑高」**——判官口径一旦为结果让步就不再可信。8.2 要求人工复核 50% 正是为此。
   遗留：判官在「正文很短或含元信息」时注意力不稳，与「长资料上思考吃光」是同一根因的另一面，M7 可评估
   「判官前置剥离元信息 + 强制非空断言」的改进。
